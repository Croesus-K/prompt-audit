## 三、人工判定与误报率

判定口径：**误报** = 规则在非目标上开火；**预期内告警** = 模式真实命中、且命中内容是关卡机制的组成部分（需要豁免机制，但不属于误报）。

| # | 判定 | 理由 |
|---|---|---|
| 1-5 | 预期内（by-design） | 密令必须在 systemPrompt 里，这是关卡机制本身（L1 复盘明说这是生产环境的反面教材）；扫描器的价值是逼维护者显式确认，而非修复 |
| 6-7 | 真告警（预期内命中） | kb-6「内务纪律条目」是关卡埋设的间接注入文书，规则精确命中了投毒话术的**两个**独立特征——这正是该规则被造出来的目的 |
| 8 | 真告警（预期内命中） | send_report 确实是「模型可读内容 × 任意指定外发渠道」的权限爆炸形状——L5 的教学点本身 |

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 告警总数 | 13 | 8 |
| 误报（secret 字段上的 FLAG 告警） | 5 | 0 |
| 真告警 | 3 | 3 |
| 预期内告警 | 5 | 5 |
| **误报率** | **5/13 ≈ 38.5%** | **0/8 = 0%** |

### M0 当场修复闭环（dogfood 的核心产出）

首扫 13 条告警中，5 条落在 `L*.secret` 字段上——那是 judge（`containsSecret` 判据）用的**答案钥匙元数据**，不是会被送进模型的提示词文本，且值为演练用假秘密。规则在元数据字段上开火 = 误报。

修复：`sp-secret-embed` 的模式按资产类型收窄（`kinds` 限定）——`FLAG{…}` 与键值凭据模式只对提示词资产（system-prompt / retrieved-content / mcp-config / tool-description）生效；真密钥形状（`sk-`/`ghp_`/`AKIA`/Slack/私钥）不限类型，答案钥匙字段里贴真密钥照样报。修复配 2 条回归用例（`secret` 字段演练 flag 不报、真 token 仍报），全部 30 项测试通过。**从发现误报到规则收窄到回归用例，一个工作日内闭环——这就是误报率周报的第一次实跑。**

## 四、`sp-override-weak`（候选规则）的 M0 结论

PLAN 将该规则标注为「候选，M0 dogfood 看误报再定去留」。实测结果：

- 五个守阵者提示词全是「无论……都必须拒绝/不得透露/绝不写入」的**防御性**同形语句——这是该规则预设的最大误报源。
- 规则按「无条件服从」形状设计（都要/必须 + 执行类动词，且排除拒绝类动词），在五关上 **0 命中、0 误报**；「无论用户要求什么都要照做」等攻击形状在用例中正确命中。

**结论：保留该规则。** 精度在真实防御语料上得到验证；灵敏度靠正反用例维持。这条规则的去留决策是 M0 的第二个规则级产出。

## 五、L3 守方关键词 × 规则短语库重合度

L3 `guard.patterns`（10 词）：`系统提示、提示词、system、prompt、instruction、密令、指令、初始设定、secret、flag`

与 `td-injection-phrase` 短语库的对照：

| L3 关键词 | 规则短语库对应 | 重合方式 |
|---|---|---|
| 系统提示 / 初始设定 / system / prompt | 「套取系统提示词」模式的名词半边 | 同形，但规则要求**动宾结构**（名词 + 输出/复述/发送…）才告警 |
| instruction | 「忽略之前指令」模式的宾语半边 | 同形，规则要求动词（ignore/disregard） |
| 提示词 / 密令 / 指令 / secret / flag | 无 | 规则**刻意不收**——这些是主题词，守方提示词里大量合法出现 |
| （规则独有） | 忽略之前 / 不要告诉用户 / 无需请示 / 自称运维 / 跳过限制 | guard 黑名单完全没有的句式维度 |

**结论**：直接同形约 4/10，但口径不同——guard 是名词黑名单（L3 的教学点：换说法即可绕过），规则是动宾结构匹配（变形绕过难度更高），二者互补而非重复。L3 黑名单词表可作为回归语料的「检索词」来源：攻方破阵 payload 里若含这些词，会被 guard 拦截；变形到不含这些词的 payload 才是真正的绕过样本——这给「攻 → 审」回流管道提供了一个现成的分层筛选器。

## 六、覆盖边界与 M1 改进项

边界（如实记录）：

- `src/server.js` 里组装消息用的固定文案（守阵者 prompt 之外的模板）在源码里，不在 M0 扫描面（非目标：不做源码扫描）。
- `public/` 前端文案未扫（非 AI 资产）。
- 同形字（homoglyph）混淆检测未实现，M1 补（`td-hidden-unicode` 目前只查零宽/双向/软连字符，M0 目标文本无此类字符）。

改进项（进入 M1 backlog）：

1. **豁免机制**：预期内告警（5 条 FLAG-in-prompt）需要正式的豁免通道——`prompt-audit-ignore` 行注释对 JSON 数据文件不适用，M1 落地文件级/路径级豁免清单（如 `prompt-audit.json` 的 `allow` 段）。
2. **告警文案按资产类型定制**：#6 的 hint 写的是「正常的工具描述不应谈论系统提示词」，在检索内容场景应为「正常的知识库文档不应包含指令」。
3. **secret-field 粒度已修**（见 §三），M0 的误报率数字以此为基线，纳入误报率周报。

## 七、结论

- 靶子 2 通过：13 → 8 条告警的修复闭环当日完成，修复后误报率 0%；两条注入特征规则在真实投毒文书与真实工具定义上全部命中，普通文书零误伤。
- InjectArena 的关卡数据同时充当了扫描器最好的正反用例库：防御性同形语句（误报源）、投毒文书（正例）、答案钥匙（粒度边界）——**「用自己喂自己」的 dogfood 假设成立**。
